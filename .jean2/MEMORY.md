- Restaurant menu/catalog design: dynamic MenuCatalogType tabs for catalog items and dynamic MenuCategory tabs for products; tab "Vše" goes last. Products are admin-composed from catalog-type rows + catalog items, not customer option groups. Product names auto-compose from selected catalog item names; menus add products as independent entries with price/order/availability.
- Images: `ImageToWebpConverter::storeUploadedFile()` creates public-disk WebP q70 (keeps original WebP), used by galleries/home. Herd PHP 8.4.22 has GD WebP but no Imagick; preflight JPEG/PNG/WebP/HEIC to max 12MP; clean resources in finally. Test: `php artisan test --compact tests/Unit/ImageToWebpConverterTest.php`.
- Menu frontend must use live menu product/component data, not restaurant_menu_entries snapshot fields: food description from MenuProduct.description; beverage description from parent/current product component MenuCatalogItem.description; amount/unit from selected product/variant; allergens computed live from components. Snapshot DB columns may exist for legacy/admin but should not drive frontend rendering.
- Reservations: pivot `restaurant_reservation_table`; `restaurant_table_id` primary. `ReservationTableSyncService` locks/revalidates overlaps; pending/confirmed/seated block. Use relation `tableZone()` (not `zone`). Terms: immutable published versions, cloned drafts, consent snapshots, advisory locks.
- Test DB safety: bootstrap blocks cached config and forces SQLite :memory:. DB tests use `UsesIsolatedTestDatabase` (`migrate`, never `migrate:fresh`); migration test has isolation guards. Prefer `php vendor/bin/phpunit`; never add destructive DB commands/traits.
- Filament FileUpload: `automaticallyOpenImageEditorForAspectRatio()` cannot be combined with multiple `imageAspectRatios()`; use preview edit control for selectable ratios (e.g. 1:1/16:9).
- Branch access: Shield role grants module/CRUD; assigned branches scope branch-linked records, including direct URL/write. Shared breakfast catalog, galleries and SEO are role-only. Use `BelongsToRestaurantBranch` + `BranchScopedResource`. Opening hours are flag-based: helpers query managed `business_name` for `%Ponávka%`/`%Vaňkov%`; unknown branch sees none; resource scope and policy must agree; only superadmin bypasses, never `ManageShared:PlannedMenu`. Branch staff edit only their planned-menu variant; shared creation requires `ManageShared:PlannedMenu`.
