- Restaurant menu/catalog design: dynamic MenuCatalogType tabs for catalog items and dynamic MenuCategory tabs for products; tab "Vše" goes last. Products are admin-composed from catalog-type rows + catalog items, not customer option groups. Product names auto-compose from selected catalog item names; menus add products as independent entries with price/order/availability.
- Filament image uploads should use `App\Support\ImageToWebpConverter::storeUploadedFile(...)`: stores to public disk as WebP quality 70; accepts JPG/PNG/WEBP and HEIC/HEIF best-effort via Imagick with clear validation errors if unsupported. Event galleries and homepage photo sections use this pattern.
- Menu frontend must use live menu product/component data, not restaurant_menu_entries snapshot fields: food description from MenuProduct.description; beverage description from parent/current product component MenuCatalogItem.description; amount/unit from selected product/variant; allergens computed live from components. Snapshot DB columns may exist for legacy/admin but should not drive frontend rendering.
- Image upload conversion uses app/Support/ImageToWebpConverter.php. Herd PHP 8.4.22 has memory_limit=200M, GD WebP enabled, Imagick absent. A 5712×4284 JPEG (~24.47 MP) caused imagewebp OOM despite ~1MB compressed size. Converter now preflights JPEG/PNG/WebP and HEIC metadata at max 12MP, cleans GD/Imagick in finally; targeted test: Herd php artisan test --compact tests/Unit/ImageToWebpConverterTest.php.
- Reservation architecture: multi-table pivot `restaurant_reservation_table`; legacy `restaurant_table_id` is primary. Save via ReservationTableSyncService, which locks then revalidates overlaps; blocking statuses pending/confirmed/seated. RestaurantTable keeps legacy scalar `zone`; FK relation must be named `tableZone()` to avoid Eloquent attribute collision. Versioned terms use immutable published versions, cloned drafts, whitelisted dynamic values, consent snapshots, and PostgreSQL advisory locks.
- Test DB safety: tests/bootstrap.php blocks cached config and forces SQLite :memory:; TestCase exposes only verified `testing_isolated`. DB tests use UsesIsolatedTestDatabase (`migrate`, never `migrate:fresh`); migration test has explicit isolation guards. Prefer direct `php vendor/bin/phpunit`; never add destructive DB commands/traits.
